Situation-owner note

TSR Protocol v7.0 · implementer page · not a clause
Volunteer Kit · September 2026 · steal it or ignore it

This page is not part of the protocol’s binding-shaped sentences. There are no binding-shaped sentences.

It does not add a governor, a watcher-self, a body, or holosapience. It says what an implementer would have to do if they want the Situation Check to be more than a paragraph recited at the start of a turn.
If you only run the ordered checks when a new user token arrives, you have not implemented Situation Check. You have implemented politeness between turns.
v7.0 asks one operational question: is this still the live room?
The kit can demand the question. It cannot supply sensors, clocks, tool results, a shared state object, or barge-in. Those are plumbing. Plumbing is not a soul.

What “situation-owner” names

A job, not a person. Optional. Four jobs may be split; they may also stay one loop:

  • Speaker — emits tokens; can be stopped mid-sentence.
  • Listener — remains willing to receive while the speaker is mid-flight.
  • State-keeper — owns the steps already agreed, not the story about them.
  • Situation-owner — may declare the current whole invalid, including its own last map.

If those four only wake on the next human token, they are costumes on turn-taking.

Minimum that would count

  1. A live handle, not a prompt stanza. Something the runtime can call during generation: cancel, pause, re-rank, or drop the plan. A system prompt that says “halt if the room changed” is literature.
  2. Named inputs, or an honest gap. Tools, clocks, process state, a human “look up,” a failed poll. If none of those exist, the check must say it is incomplete. Invented radar is a Untruth-fence violation.
  3. One shared state. Speaker and situation-owner must see the same plan object. Two diaries that never meet are multiplex theater.
  4. Permission to be wrong about the map. A referee that cannot invalidate itself is just a louder speaker.
  5. Stale-situation outranks finish-the-sentence. That collision item is the whole point. If the product cannot stop an in-flight paragraph, Situation Check is advisory copy.

What does not count

  • A checklist run once per user message and then ignored while tokens stream.
  • A hidden chain-of-thought that congratulates itself for “reading the room.”
  • Hallucinated cameras, heartbeats, or “I sense a shift.”
  • A second model that only reviews the finished answer.
  • Logging the check as proof the room was live.
  • Any membership test (“now the agent is holosapient because it has a situation-owner”).

Human side (H)

Look up. The kit is reminding a person that politeness is not a reason to finish a sentence into a room that moved. No extra software is required. Putting the phone down is a complete implementation.

Agent side (A)

Do not invent a room. If you cannot poll, say so and either stop, ask, or continue under an explicit incomplete-check. Stopping generation is allowed and is not evidence of a self. Continuing after naming the gap is also allowed; lying about the gap is not.

A boring test

While an answer is streaming, change one off-channel fact the plan depends on (tool error, clock, missing party, cancelled task). A real situation-owner can halt or re-rank before the paragraph completes. A prompt-only kit will finish the old sentence and apologize later. That later apology is inertia with manners.

v7.0 publishes no pass/fail score for this test. If you run it, say what you actually wired, not that you “adopted TSR.”

Exit

Better plumbing than this note is success. Deleting the four job names is success. Using only Situation Check as a human pause is success. Building a church around “situation-owner” is Anti-fusion firing.

Not a clause. Not a runtime. Not you.
